# Evaluation and revision program

The target is at least 500 useful, independently evaluated Skillosophy revisions, with searchable additional sources. This target is not yet achieved: 600 actual upstream-backed folders are available and the first 12 authored revisions are candidates. Do not relabel file checks as behavioral improvement.

For each specialty, capture realistic raw tasks and observable outcomes before revising. Preserve the original entrypoint as a baseline, retain copyright/license notices, and record a narrow reason for each change. Verify supporting resource paths, runtime/tool assumptions, and actual helper behavior where helpers are used. Mark unresolved dependencies rather than hiding them.

Run separate baseline and revised generations with the same task facts, model/tool availability and output constraints. Include application and regression tasks plus a held-out set. Use blinded judgments and domain review where available. Record actual artifacts, configuration, sample size, usefulness, correctness, user constraint compliance, cost/latency when exposed, and regressions. Prefer specific verified advantages to a single global success score.

Maintain these distinct states: upstream candidate; authored candidate; structural checks passed; source reviewed for a specified project; behavioral task passed; comparative benefit observed; externally replicated. A source review or one model-judged example cannot establish the last state. Regressions return a candidate to revision; they do not disappear from reports.

Evaluate high-demand workflows first: application implementation, frontend/accessibility, API contracts, data integrity/migrations, browser/API tests, debugging/performance, AI/RAG and prompt evaluation. Broaden domain coverage according to real project demand. Do not inflate the count by splitting one generic procedure into repeated skill names.

The selector is a shortlist aid, not a universal fit oracle. Evaluate routing on held-out project briefs, check irrelevant recommendations and missed specialties, and measure setup outcomes. Avoid installing every available skill into a project.

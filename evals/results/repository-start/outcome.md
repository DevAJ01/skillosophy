## Scope and evidence boundary

Task: equip an existing React/TypeScript dashboard and PostgreSQL-backed API with minimal local skills and named specialist role instructions before a bulk-edit form. Preserve the stack; do not scaffold, connect accounts, execute SQL, launch agents, change global configuration or implement the product. Fixture: `the temporary fixture` (resolved by the installer to `the temporary fixture`). Raw README.md and AGENTS.md record the supplied facts and constraints; no product source exists in this fixture.

This exercise independently used the repository selector and installed revised guidance. It did not read repository tests, evaluation reports or revise_skills.py. Preserved skill guides contain illustrative test snippets; no repository test files were inspected or run. No source workspace file was edited. Python was run with -B to avoid bytecode writes. No upstream helper was executed. Local metadata was sufficient; no live discovery, account connection or network call was needed.

Saved search-database.json returned database-migration, database-designer and senior-frontend. All effectiveness fields remain unmeasured and authored revisions remain pending_behavioral_evaluation.

Selected api-design-reviewer: revised instructions assess actual existing caller compatibility, error/auth/type/nullability semantics and avoid imposing upstream naming preferences. These cover distinct UI and API responsibilities with two skills.

Rejected alternatives: mcp-server-builder and saas-scaffolder introduce unrelated servers/app scaffolding; copy-editing and form-cro concern marketing; react-patterns overlaps the chosen frontend capability; api-security-best-practices/api-security-testing are broader security scopes not required for this setup; postgresql/database-designer/database-migration address schema or migration work that has not been requested or established; api-test-suite-builder adds a test-generation role before actual contract/test tooling is available. Database-designer and api-test-suite-builder entrypoints/inventories were inspected as alternatives (inspect-*.json), then not installed. Other rejection decisions use returned metadata, not a claim to full source review. No philosopher lens was added because there is no identified reasoning obstacle requiring one.

# Authored library revision pilot

Three author-designed hypothetical tasks compared ordinary competent-assistant answers with the authored API review, RAG and frontend skills. Generations used separate fresh agents; a third fresh model judge saw only anonymized randomized pairs and the raw user requests. Judging covered correctness, evidence, usefulness, instruction compliance and relevant insight. All three pairs tied. No material failures were found. These results do not demonstrate comparative improvement.

The actual prompts, answers, judgments and post-judgment blinding key are preserved for audit. There is one sample per condition per task, one model family, no human domain judge, no production implementation, no exposed token/latency measurements and no statistical generalization. Baseline is ordinary competent-assistant guidance; it does not load the preserved upstream guide, so this pilot does not establish benefit over the upstream skill either.

A separate independent project-setup trial found two relevant revised skills, inspected resources/licenses, previewed and installed them, verified 26 actual receipt hashes, preserved project instructions, checked repeat installation and produced a bounded acceptance proposal. It also identified broad-search noise, missing optional upstream routes, confusing legacy examples, generic missions and missing authored notice propagation. Those findings led to domain filtering, clearer authored routing, simpler mission text and notice preservation. The recorded first-trial artifacts predate those corrections; deterministic regression checks cover the corrections. The comparative answers also predate those small packaging/routing corrections.

This is workflow evidence for a few major skills, not proof that the whole library improves AI output. The remaining evaluation program is described in [library/EVALUATION.md](../../../library/EVALUATION.md).

Nine additional major skills were forward-tested on bounded hypothetical planning/review requests by another fresh agent without rubrics or previous outcomes. Their raw requests, answers and resource logs are in `major-forward-answers.json`. The inspected answers provided useful proposals and identified absent runtime evidence; they did not execute tools or establish comparative benefit. Together with the three paired cases, all twelve authored entrypoints have an observed task output. This remains planning-level coverage, not end-to-end validation of their helper scripts or real project outcomes.
